# 受管理虛擬機控制

[English](hypervisor-controls.md) · [桌面文件](../desktop/README.md)

客體工作區透過既有主程序操作服務支援 VirtualBox 同 VMware。拓撲工具列偵測供應程式，只列出由程式管理嘅記錄。偵測只報告指令可用，唔係客體成功啟動驗收。

## 接納執行檔

偵測或操作客體前，先開 Tools，重新整理執行檔清單，透過原生選擇器選已安裝嘅 `VBoxManage.exe`、`vmrun.exe` 或 `qemu-img.exe`。原生信任對話框顯示確切解析路徑同 SHA-256，預設係 Cancel。只有明確批准先執行固定探測並保存本機身分收據。渲染器提供工具識別碼，唔提供指令、執行檔路徑或參數清單。

每次部署呼叫都會重新解析收據，檢查絕對路徑同目前 SHA-256，再交畀固定參數消費端。未接納或執行檔已被取代會停止操作，唔會退回裸名稱或 PATH 搜尋。安裝更新令位元組改變時，要重新選取並批准。收據係使用者信任決定，唔係廠商簽署或發行者認證。VMware 使用唯讀執行狀態可用性探測，版本記為未驗證；偵測唔會回傳客體路徑。需要磁碟檢查、建立或轉換時，要先接納 QEMU。

## 建立或匯入

由新客體草稿開始。新草稿重設為 NAT、BIOS、2048 MiB、兩個 CPU，冇附加媒體。最多加四個網絡配接器同四個儲存附件。VirtualBox 橋接同 host-only 需要已偵測介面；VMware 使用供應程式自己管理嘅介面選擇。數值無效、媒體選擇空白、欠必要介面，或供應程式觀察為不可用時，Create 會保持停用。

使用 Guest records 同磁碟轉換，將已驗證輸出磁碟匯入成新受管理客體。設備封存檔唔獲接納。VMware VMDK 輸入要通過既有受管理轉換路線。後端將已接納來源媒體複製到管理目錄，唔修改來源同共用輸出磁碟。卸下媒體仍會保留管理副本。

## 配置同操作

選已停止客體，編輯拓撲，預覽確切變更，批准預覽後先套用。預覽修訂、到期時間同主程序驗證仍係依據。Guest records 只編輯硬件時會保留全部配接器同媒體，網絡修改由拓撲編輯器負責。

拓撲工具列可重新整理供應程式狀態、要求啟動已停止客體，或要求正常關閉執行中客體。啟動同關閉要求都包括所選記錄修訂。關機要求唔代表已關機，要重新整理觀察結果。供應程式程序執行中唔代表客體已開機。未知同部分建立狀態會明確保留，唔會啟用 Launch。

切換項目會清除上一個客體、拓撲、供應程式偵測同媒體清單。選新草稿會清除所選客體拓撲。重新整理記錄會同步所選記錄，並令舊預覽失效。切換供應程式會清除前一個嘅介面名稱。以上動作唔會執行主機虛擬化指令，直到選擇相應明確操作為止。

## 交付證據

原變更只連接來源流程。其限定交付模式冇執行測試、靜態分析、審查、擷取，或原生建立、匯入、配置、啟動同停止驗收。主要協調任務另行記錄製作結果。原生執行驗收同保留證據仍待處理。
