# BIOS ISO 製作與匯出

[English](iso-production.md) · [引導工作流程](iso-workflow.zh-HK.md)

## 先準備來源同配置

映像流程提供綁定來源嘅 x86-64 BIOS ISO 計劃。先選可信任嘅 Buildroot 來源，再配置 x86-64 架構同 Linux 核心，例如使用來源提供嘅合適 defconfig。計劃會一併要求 GRUB2、舊式 BIOS 平台、ISO9660、GRUB2 ISO 開機載入器同 initrd 選項，設定光碟開機分割區同內置 ISO 模組，並停用衝突嘅 Syslinux/UEFI 選項。佢唔會安裝桌面環境或配置 UEFI。

Preview 讀取來源即時 Kconfig 符號同目前配置修訂。Apply 只接受該修訂，使用既有配置交易並執行 `olddefconfig`。原有配置復原功能仍可用。結果會明確報告每個 ISO 選項係咪喺協調後保留。有效結果為 false，就代表配置未完成，即使協調程序正常結束都一樣。

## 提交同製作

引導提交使用 `imagePreset.isoBuild`，綁定最後一次成功而有效嘅 Apply 所回傳嘅設定同修訂。主機持有同一項目及配置租約，重新檢查批准修訂同有效值，再擷取並排入既有建置意圖。復原、取代設定或移除必要選項，都會令引導提交失效。提交後仍需通過排程器來源及配置摘要檢查。一般手動建置係另一條路線，唔代表引導 ISO 已準備好。

套用計劃後，透過建置佇列執行完整建置。ISO 目標成功時，Buildroot 會喺所選輸出目錄產生 `images/rootfs.iso9660`。建置必須喺認可、非 root 嘅 WSL 2 或 Linux 容器環境執行。ISO 流程唔會取代既有輸出目錄。新輸出樹可能需要下載大量工具鏈、Linux、開機載入器同主機工具。

## 執行記錄同限制

Linux 建置子程序會保留有效絕對 Linux 工具鏈 PATH 項目，移除繼承嘅 Windows 掛載、相對路徑同包含空白嘅項目，再附加標準 Linux 工具目錄。主機同發行版配置唔會改變。

執行期間會串流真實記錄，合併輸出上限為 256 MiB，完成記錄每條串流最多保留 1 Mi 個字元。超過總上限會明確失敗，並清理所屬程序。其他程序呼叫者仍使用原有較小預設。

## 檢查、匯出同啟動證據

匯出前先檢查產生嘅檔案。檢視器報告 SHA-256、大小、ISO 卷描述符一致性同有限範圍 El Torito 目錄檢查，包括驗證項目校驗和同首個開機項目位置。無效、缺少或超出範圍嘅結構會保持可見。呢啲係結構檢查，唔證明韌體成功啟動、核心開始運作或有可用 shell。UEFI、混合 USB 同其他預設或韌體組合，都需要獨立配置同執行驗收。

ISO 匯出逐位元組複製既有 ISO 到新名稱，再驗證校驗和。佢唔會靠改名將磁碟映像變成可啟動 ISO。目標已存在會拒絕操作，原始內容保留。匯出預覽會到期，來源改變亦會令預覽無效。某個輸出嘅啟動驗證必須等到同一映像有獨立證據先可成立。

已記錄嘅特定產物係 12,357,632 位元組，SHA-256 為 `1d75d40b94e3c441aaaead9109f8074f62334931e1d84a576f3d7a36ec566dba`。未修改映像喺 QEMU 10.0.13、Cirrus 顯示同 RTL8139 網絡組合啟動 Linux 6.12.9，完成主控台、暫存檔讀寫、DHCP、內部閘道回覆同正常關機。呢個結果唔證明重啟後資料保留、互聯網、區域網絡、其他顯示卡或其他虛擬機相容。請讀[製作記錄](../evidence/iso-production/README.md)同[完整啟動界線](../evidence/iso-boot/README.md)。候選原生介面同發佈版本仍需各自驗收。

## 輸入安全界線

`imagePreset.isoPlan` 同 `imagePreset.isoApply` 只接受工作區身分同配置修訂。渲染器唔可以透過佢哋提供 shell 指令、額外 make 參數、開機載入器路徑或配置片段。
