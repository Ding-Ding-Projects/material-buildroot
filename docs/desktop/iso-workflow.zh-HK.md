# BIOS ISO 工作流程

[English](iso-workflow.md) · [欄位目錄](iso-fields/README.md)

映像預設面板提供明確流程，適用於已採用、已啟用 Linux 嘅 x86-64 項目。佢會讀取所選來源目前真正提供嘅配置能力。

## 由檢查到檢視輸出

1. **Check ISO prerequisites** 讀取目前修訂，預覽固定嘅 GRUB2、ISO9660 同初始 RAM 檔案系統要求。唔支援嘅條件會保持可見。重試前先選合適嘅 x86-64 Linux 開發板。
2. 檢視要求、批准，再選 **Configure BIOS ISO**。主機會重新協調 Kconfig。只有全部必要值仍然有效，**Build ISO image** 先會啟用。呢個只代表配置成功，唔代表映像已製成。
3. **Build ISO image** 會用已儲存嘅 WSL 或 Docker 環境，以兩個並行工作提交 `all` 目標。**Refresh ISO job and log** 讀取真實工作同最先 50 筆記錄。**Cancel ISO build** 會要求取消該工作身分同序號。
4. **Inspect ISO output** 經受限主機讀取器檢查 `images/rootfs.iso9660`，顯示位元組數、SHA-256 同 ISO 描述符及 BIOS El Torito 結構結果。舊檔可能屬於之前嘅建置；單次檢查唔會將佢綁定到最新工作。

## 範圍與復原

此設定只處理 BIOS。UEFI、其他架構，同完整桌面、伺服器或設備預設覆蓋，唔屬於此路線。ISO 匯出只複製現有 ISO，唔會將原始磁碟變成可啟動光碟。

開始前先配置並授權執行環境。下載同編譯可能需要相當時間。流程唔接受 shell 指令、任意符號或路徑輸入。修訂衝突需要重新取得計劃。協調後冇保留嘅值會明確標記未完成。原有編輯器仍可復原配置。

切換工作區會清除 ISO 計劃同檢查狀態，舊回覆唔可以填入新工作區。更改其他預設會令準備狀態失效。流程唔刪除無關輸出；正常增量建置仍可能更新產生嘅檔案。Inspect 唔會啟動或掛載映像。

## 驗證界線

有型別渲染器測試資料驗證要求次序、停用狀態、未完成配置、工作區隔離同檢查用語。呢啲唔證明原生 IPC、真實 Buildroot 製作或可啟動性。執行驗收要另外記錄來源、配置、工作、輸出雜湊同實際啟動結果。建置成功加有效中繼資料，仍然唔夠作啟動證據。

目前已有[製作證據](../evidence/iso-production/README.md)同[特定消費端啟動證據](../evidence/iso-boot/README.md)。證據綁定指定映像同測試組合，唔會將此候選介面變成已安裝發佈版本嘅證明。

## Easy 同 Advanced 模式

Easy 模式自動讀取所選來源同已儲存環境，下拉清單顯示實際偵測到嘅值。Advanced 模式保留原有預設同完整配置編輯器。每組 ISO 欄位有可展開嘅說明，同開啟內置文件文章嘅按鈕。執行環境選擇同自訂資源預留仍喺原有專用控制項，此流程唔聲稱來源全部能力都有圖形介面。

Easy 模式有三個 Back/Next 步驟：準備偵測到嘅光碟設定、製作映像、檢查結果。裝置只會按工作區儲存步驟、模式同工作身分。恢復時唔會將配置成功或已檢查輸出還原成事實。新建置之前要重新檢查配置，找回工作後要重新整理。瀏覽器儲存失敗會清楚顯示。畫面解釋產生嘅檔名，唔會提供未支援嘅改名欄位。

引導製作使用原子 `imagePreset.isoBuild` 主機操作，持有配置租約期間將最後成功套用嘅修訂同設定組合綁定到建置。外部配置修改會令面板準備狀態失效；主機亦會獨立拒絕過期或未生效配置。較早嘅 Syslinux 6.03/gPXE 路線喺受測來源環境遇到 GCC 13 內部編譯器錯誤，因此此設定改用 GRUB2 BIOS，唔聲稱所有編譯器都相容。
