# WSL 設定及 Linux 儲存

[English](wsl-runtime.md) · [功能索引](README.md)

「專案及執行環境」有獨立 WSL 面板。探索只列出已登記發行版及 WSL 版本，唔啟動。檢視會明確啟動所選 WSL 2，檢查預設帳戶非 root、home 係普通 `/home/<user>`，以及常見 Buildroot 主機指令存在。

## 設定操作

- 選擇現有 WSL 2 並檢視準備狀態，WSL 1 唔可用於設定。
- 原生確認後可喺 Debian/Ubuntu 安裝缺少工具，固定套件管理指令以 root 執行，Buildroot 本身始終用非 root 預設帳戶。安裝要網絡；工具存在唔證明所有 Buildroot 版本相容。
- 「取得專用 Ubuntu」從 `releases.ubuntu.com` 下載官方 Ubuntu 24.04.3 WSL 映像，匯入前核對鎖定 SHA-256。HTTPS 唔跟轉址，最多 2 GiB、30 分鐘，未完成檔案保留，匹配快取重算摘要先重用。
- 原生選擇器可匯入可信 `.tar` 或 `.wsl` Linux 根，每次用唯一專用發行版名稱同儲存目錄，唔取代現有登記。匯入前寫受管理記錄，匯入或帳戶設定未完成仍保留。
- 新管理發行版建立 `materialbuilder` 非 root 帳戶並要求 WSL 設為預設；舊 WSL 冇預設使用者管理就明示未完成。壓縮檔要有 Debian/Ubuntu 相容帳戶工具，不支援就保留供手動復原。
- 喺非 root home 準備 `source`、`output`、`downloads`，保留現有內容，拒絕符號連結替代。
- 原生檔案瀏覽器只開由所選登記發行版同已驗證 Linux 儲存構造嘅路徑，唔接受顯示層 UNC。
- 可將所選發行版匯出到原生所選目的地下全新獨佔資料夾。原生確認會指出備份可能有秘密，執行中工作可能令內容不一致。部分匯出保留並標未完成，唔停止、取消登記、覆寫或刪除發行版。

## 必要條件及復原

WSL 2 要受支援 Windows、硬件虛擬化及 WSL/Virtual Machine Platform 功能。面板說明但唔啟用作業系統功能或者重啟，必要重啟由使用者手動做。取消或者 WSL 不可用唔等於準備成功。

設定唔改現有發行版預設帳戶或者登記。管理匯入喺帳戶初始化中斷可以再檢視，手動修復要保留檔案系統及管理記錄，唔自動刪除回復。記錄只喺程式本機資料，唔入遙測或報告匯出。

## Linux 專案權限及限制

專案流程準備資料夾，可選擇將官方 Buildroot 複製到空來源，再開只限該發行版工作區嘅來源/輸出選擇器。獨立原生確認批准來源執行，專案沿用現有佇列、預留、擁有權、取消及復原，綁定同一發行版。

主程序專用收據綁定發行版、boot、機器身份、非 root uid、Linux 根/來源/輸出裝置及 inode，拒絕符號連結、跨裝置、非 Linux 檔案系統及來源輸出重疊。實際建置程序喺擁有權握手前再次核對，探測及之後處理端亦驗證。只持續儲存有型別儲存資料，重啟或取代發行版要再選資料夾授權。普通 UNC/網絡授權仍被拒絕，所選路徑目前要簡單 ASCII 組件，唔含空格。

專用[來源修訂](source-lifecycle.zh-HK.md)流程已接通收據綁定升級及回復，唔提供普通主機授權，實際驗收仍未完成。WSL 外部樹啟用仍不支援，唔擴大 Linux 根。設定及建置可用已接入來源/輸出配對，但此交付模式唔證明完整執行。
