# GitHub 執行設定

[English](setup.md) · [執行索引](README.md)

執行環境有引導面板，選擇現有來源，同一個或者另一個既有專用執行來源。輸入明確 `owner/name`。存取檢查使用主機已登入 GitHub CLI 帳戶。固定 CLI 取得、選可信現有執行檔及裝置登入係分開明確控制，唔自動建立來源、配置 runner 或開始建置。

主機以固定 `gh api` 讀認證帳戶同存取，顯示層唔可提供 CLI 參數、執行檔路徑、API 主機、憑證或者任意端點。移除憑證環境覆寫，使用 CLI 認證儲存。錯誤有界，原始 CLI 診斷唔回顯示層。

選擇只留記憶體，30 分鐘到期，重啟要再做。每次遠端操作重新核對帳戶。來源同目的地必須符合 GitHub 回傳身份，目的地要可寫，唔可以已封存或停用。來源寫入權唔代表 workflow 發佈權，後者要由發佈獨立建立。

私有來源去另一個執行來源目前被拒絕，因未支援適當跨來源讀取憑證，唔猜測或者複製憑證繞過。

runner 探索最多十頁可見清單。自管選擇要 Linux、X64、online 同 not-busy，缺少管理權限明示不可用，唔當空成功。固定託管選擇為 `ubuntu-24.04`，唔保證可用或者帳戶費用。每個選擇都要明確確認費用及容量，自管確認時再更新清單，唔預留容量或配置機器。

可信主機向 workflow 同工作服務提供選擇及傳輸輔助。JSON 回覆最多 2 MiB、30 秒，串流十分鐘。二進位輸出直接串流至主機授權目的地，呼叫方上限最多 1 GiB 加 32 MiB。大小及 SHA-256 相符先獨佔建立最終檔案，取消、逾時、驗證失敗保留非空部分檔案並標未完成，只刪空暫存檔，唔整份放入記憶體。選擇 handle 唔係憑證，唔持續儲存或匯出。

## CLI 取得及登入

`src/main/execution/gh-release.json` 記錄產品同發行啟動共用固定版本及壓縮檔摘要。只從 GitHub 以 HTTPS 轉址 allowlist 下載該檔，最多 100 MiB、三分鐘。先核摘要，再只解壓 `bin/gh.exe` 至新專用目錄，唔取代現有安裝。執行檔路徑及 SHA-256 本機登記，每次啟動再查，改變要重新批准。亦可用原生選擇器接入可信執行檔。

使用者明確揀登入先執行 `gh auth login --hostname github.com --git-protocol https --web --scopes workflow`。CLI 管理瀏覽器授權及憑證，面板只顯示解析後有界裝置碼、固定 `https://github.com/login/device` 同生命週期，唔顯示或保存原始程序輸出。取消停止本機程序同清除碼，唔宣稱撤銷已完成 GitHub 授權。嘗試本機十分鐘到期；CLI 警告不安全儲存時顯示安全儲存未完成，唔報準備成功。

官方行為見 [CLI 登入](https://cli.github.com/manual/gh_auth_login)及[環境](https://cli.github.com/manual/gh_help_environment)。

## 驗收狀態

只有來源實作，此輪未測試、靜態分析、執行、擷取、認證、修改來源、發佈 workflow 或派送建置。固定取得、執行檔信任、裝置流程、串流取消及完整產品驗收仍未核實。
