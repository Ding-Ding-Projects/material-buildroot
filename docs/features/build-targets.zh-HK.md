# 具名建置及套件目標

[English](build-targets.md) · [功能索引](README.md)

建置工作區提供固定整體專案目標同由來源探索嘅套件操作。揀選目標唔會執行，先檢視執行環境、並行數及資源預留，再用既有排隊操作提交。

## 整體專案目標

| 目標 | 用途 |
| --- | --- |
| `all` | 建置已設定系統及最終映像 |
| `sdk` | 用已授權執行環境及佇列產生可搬移 SDK，匯出使用獨立流程 |
| `source` | 取得已設定來源 |
| `legal-info` | 產生目前設定嘅授權資料 |
| `show-info` | 輸出套件資料 |
| `graph-depends` | 所需主機工具可用時產生依賴圖 |
| `clean` | 移除產生嘅建置輸出；Buildroot 保留設定，但系統要重新建置 |

## 套件操作

套件名稱由已接入來源 `package/` 及已授權外部樹 `package/` 下相符目錄與 `.mk` 檔名探索。只讀目錄，唔求值 makefile，跳過符號連結，最多五層及 30,000 項。其他自訂佈局唔列出。探索唔證明套件已啟用，亦唔證明目前設定有該目標。

主機只接受有界套件名稱加以下後綴：`-download` 取得來源；`-rebuild` 再編譯而唔重複設定；`-reconfigure` 再設定及編譯；`-dirclean` 刪除套件建置目錄，下一次重新建置。

重建套件唔會自動重建反向依賴或者最終映像，之後要執行 `all`。工具鏈、架構、ABI 或其他不相容變更可能需要先 `clean` 再 `all`。套件清理唔會移除 staging 或 target 全部舊安裝檔，唔係解除安裝。

## 確切目的地確認

整體同套件清理都要通過既有雙核取鍵、滑桿及重建確認，綁定主機解析嘅輸出目錄、目標、執行環境、工作區身份及請求。取消或者到期唔會排隊。顯示層唔可提供指令、shell 片段或者目的地路徑，執行層會再次核對套件存在。

所有操作沿用不可變佇列意圖、來源與設定快照、工作區租約、執行環境權限及非 root 執行。排隊後意圖改變會阻止准入，唔會偷偷更新。清理重試必須取得新確認。

## 歷史及即時輸出

面板開啟時每兩秒讀取目前專案工作。選中工作會串流已儲存記錄，每次最多 100 個事件，畫面保留最新 500 個；顯示上限唔刪除完整歷史。執行及取消中顯示未定進度，因為 Buildroot 冇可靠總百分比。取消仍待實際終止記錄，失敗、已取消及中斷記錄保留，輸出可能不完整。
