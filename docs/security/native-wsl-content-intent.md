# Native WSL content intent and configuration consent

WSL projects capture content inside the admitted non-root Linux filesystem. Host traversal of UNC paths is unsuitable for native Linux links and can report a valid link as an unreadable directory. The fixed application-owned Python helper executes in memory, without copying the selected source to Windows or writing helper files into the source or output tree. Only aggregate digests, counts and bounded disposition metadata return to the application.

Version 3 receipts retain the existing shared limits: 50,000 entries, 512 MiB combined bytes, 64 MiB per source file, 10 seconds of capture work and depth 64. Source and configuration bytes are read without following file-open links, hard links and special files are rejected, and identities are checked before and after reading. Every traversed link component must belong to the captured namespace. Existing referent content must be captured; missing targets must remain absent. An external intermediate alias is rejected even if its final destination returns inside. Chains and saved identities are checked again before a receipt is issued.

The only separate file-size disposition is the declared Buildroot default download cache. It applies when the effective configuration has exactly `BR2_DL_DIR="$(TOPDIR)/dl"` and the corresponding cache directory is an identity-verified ordinary directory inside the admitted source. Every cache byte remains hashed and contributes to the same shared entry, byte, time and depth limits. Cache archives have a fixed 256 MiB per-file ceiling; source files retain the 64 MiB ceiling. Unsupported or duplicate declarations, cache aliases, oversized content and mutation are rejected. Cache identity, exact declaration digest and aggregate cache-content digest remain part of the intent, rather than being silently excluded.

Configuration consent, queue submission, dispatch-time checks and scheduler revalidation use the same runtime-aware capture route. Legacy host receipts that only hash link text remain insufficient to authorize linked Kconfig sources. Native receipts permit those sources only after their stronger link and content checks succeed. Configuration permission can execute admitted source-native Make and Kconfig inspection commands; a successful permission or catalog inspection does not prove a full firmware build.

The transport verifies the admitted WSL project before and after capture, checks its identity again inside the worker, records the exact owned session before submitting input and requires verified cleanup. Cancellation and unavailable cleanup remain explicit failures. The configuration inspector retains its source/runtime binding and uses the admitted Linux path mapping rather than asking the host filesystem to reinterpret Linux links.
