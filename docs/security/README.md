- [Opt-in HTTPS companion](companion.md)

The parser accepts data only. The broker adds a trusted-host settings transaction and strict reply/event translation. Local preferences use an owned-frame IPC bridge. Those IPC-only boundaries do not require a Postman collection.

The opt-in companion separately exposes authenticated HTTPS endpoints for pairing, session discovery, scoped actions and disconnection. The [current pairing article](../features/browser-pairing.md) and [admitted consumer article](../features/companion-consumers.md) describe its current authority and privacy limits. Its category-level [Postman collection](postman/companion.postman_collection.json) and the product [master collection](../postman/material-buildroot.postman_collection.json) now list four session routes and 107 typed actions from the integrated consumer contract. Both are generated by `node scripts/api/generate-postman.cjs`. The original `tests/postman-collections.test.cjs` fixture covers its historical baseline; no new action, pairing-header, real Postman or runtime acceptance is inferred. Collections contain placeholders only. Keep populated challenge, CSRF and client-instance values in unshared current values. Read the [API workflow](../postman/api-workflow.md) before use.
