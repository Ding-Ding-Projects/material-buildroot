Group A bounded semantic-detail reconciliation

Scope and verdict

PH01-T01-C02-A reviews exactly five existing identities: language, funny-emoji, personal-vocabulary, school-mode and narration. Independent source review and refutation support 15 separate detail additions: two, six, four and three respectively, with none added to language. Several formalize existing reconciliation notes. This is a bounded planning unit, not product delivery or full 109-identity acceptance.

The complete proposed inventory contains 109 identities, 436 independent A/D/C/R records and 427 planned requirements. All prior 412 requirement IDs and their text remain unchanged. All added rows remain planned; surface implementation and proof states are unchanged. Required A/D/C records remain required and R remains outside catalogue scope for these five identities. Excluded records retain complete planned-ID bindings without becoming implementations.

Source and privacy boundary

The reviewed owner-contract revision is 13b4fb30ddcd1c7a4af6989a985ceae43af4f0eb. Source correspondence is opaque; no private heading, path, payload, source URL or private content digest is published. Existing inherited source revisions and hashes remain historical rather than being relabelled fresh proof. New detail rows carry their own current source revision.

Narration catalogue scope explicitly names A+D; retained C delivery derives from the universal interface rule. Quiet-hours and reduced-sound behavior applies where those settings exist. Browser shared-mode propagation still needs an explicit capability adaptation and actual proof. No vault, credential, installation or native-host acceptance is asserted.

Added stable detail clauses

Requirement ID Planned detail
funny-emoji-REQ-05 At every humor level, preserve the exact affected file, account, action, irreversible consequence, actual error and available choices. Humor must never mock the user, data loss, money or disability.
funny-emoji-REQ-06 Keep the dialog emoji toggle localized and keyboard-accessible in each surface settings. Turning it off removes only decoration and preserves identical factual copy. Verify persistence, visible focus, accessible control text without emoji and narrow layouts in both states.
personal-vocabulary-REQ-05 Use a semantic local JSON picker with keyboard and screen-reader operation and an adequate touch target. Settings search and the command palette index and focus upload, status, replace and clear/reset controls. Each owned picker or file list has its own local filter and adjacent anchored full regex builder.
personal-vocabulary-REQ-06 Reject unknown schema versions, unsafe object keys, unexpected fields and non-string replacement values before display or caching. Do not impose a fixed minimum, exact or maximum entry count; accept every valid entry within the documented byte, depth and key/value bounds.
personal-vocabulary-REQ-07 Revalidate the private cache before every load. A missing, corrupt, stale or unsupported cache renders original wording. An invalid import preserves an existing valid selection only until explicit clear; clear purges the cache and restores original wording immediately. Never ship mappings, samples, guesses or private defaults.
personal-vocabulary-REQ-08 Exclude imported wording, cached content and source metadata from clipboard, crash reports, diagnostics, analytics, synchronized settings and user-specific evidence as well as existing excluded destinations. Exports and history disclose the omission without serializing reconstructable or identifying metadata.
personal-vocabulary-REQ-09 Apply replacements only at the private user-facing text boundary, including accessible names. Preserve commands, URLs, identifiers, code, paths and factual external records verbatim. Verify replace, clear/reset, restart, all language modes, both humor extremes, restricted-mode suppression/restoration, settings and palette discovery, keyboard/screen-reader access, narrow layouts and high scales independently per surface.
personal-vocabulary-REQ-10 Release-grade verification first checks the current owner-managed JSON generator and schema inventory, then uses the real built upload control on every applicable surface to prove valid load, applied wording, persistence, replace, clear/reset, invalid-file rejection, local-only behavior and original-wording restoration. Keep the payload out of every capture and public record.
school-mode-REQ-05 Provide the shared-mode control in each surface's own settings. Watch and apply mode, chosen-name and unlock-credential changes live across running applications. An unreadable record or unavailable watcher reports the actual unavailable state instead of assuming the mode is off.
school-mode-REQ-06 After rename use only the exact chosen name in labels, descriptions, search results, notifications and accessible names. Preserve prior settings while their capabilities are absent and restore them only after exit. Keep the mode control discoverable and accessible; any disabled-state explanation uses the chosen name and unlock route.
school-mode-REQ-07 Use one shared starting-rung decision so restricted mode starts the unlock ladder at arithmetic. The absent themed rung is not replaced with explanatory copy that reveals the hidden capability.
school-mode-REQ-08 Use one universal resettable locally verified PIN, password or passkey choice. Credential material never enters the personal-wording file, synchronization repository, source, exports, logs, telemetry, captures or version history. Explain the user-owned shared-record deletion reset without claiming a security boundary.
narration-REQ-05 Both speaks English then Cantonese through one serialized queue. Replace a superseded queued line instead of accumulating it, debounce and apply per-category cooldowns without suppressing actual error facts or recovery actions. Respect reduced-sound and quiet-hours preferences where those settings exist and yield to or duck beneath an active screen reader.
narration-REQ-06 Resolve actual voices per language at runtime, subscribe and re-read when enumeration arrives late, and unsubscribe on teardown. Persist stable platform identities. Keep an unavailable selected identity while explaining the actual fallback, network-backed offline limitation or absence of any voice for the language beneath its picker. Never ship a named-voice default.
narration-REQ-07 Rate and pitch use documented platform bounds and default to the voice's normal delivery. Each picker participates in settings search, the command palette and local version history, with keyboard focus, accessible name and description, touch targets and narrow/high-scale layouts. Keep voice names, language tags and status facts exact while localized humor styles surrounding copy. Verify all three language modes and both humor extremes.

Verification and remaining work

Source review, independent refutation, inventory preparation and preserved-ID comparison are the scope of this record. Parent application verified all 412 prior IDs and texts unchanged, then the focused ledger run passed 20 tests with zero failures or skips. The added omission case removes each of the 15 new clauses and all its bindings, and separately each C binding, proving rejection against the independent expected inventory. The restored valid ledger passes. PH01-T01-C02-A records this bounded planning result; the overall PH01-T01-C02 remains unticked. No identity is promoted to accepted or complete. No product build, runtime interaction, capture, deployment or release is established by this planning unit.

Configuration and limitations

No runtime option or HTTP API is introduced; Postman collections are not applicable. Invalid, missing or unbound planning clauses must remain validation failures. Historical evidence counts remain unchanged. These additions do not replace actual consumer, control, localization, persistence, accessibility, history, privacy or source/build-bound interaction evidence.
