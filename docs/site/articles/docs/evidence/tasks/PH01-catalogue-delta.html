PH01 catalogue delta: onboarding and per-control guidance

Compared the current canonical feature catalogue with the public inventory. The canonical catalogue contains 107 identities. The public inventory previously contained 105; exactly two obligations were absent: onboarding-wizard and info-icon-guidance. The five previously reconciled public identity aliases retain their existing IDs. No existing identity or child work ID was renamed.

Added eight independent surface records, giving 428 records. The practical in-app onboarding identity requires A only; D, C and R retain explicit exclusions for this particular identity. This does not exempt the website from its own feature delivery or contextual guidance. The per-control info-button identity independently requires A, D and C; its R record is outside this feature's catalogue scope. Broad guided-forms delivery cannot satisfy or hide this independent identity.

Added five onboarding and seven per-control guidance requirements to both the ledger and the separately reviewed expected inventory, bringing the total to 398. The new requirements cover real setup action results, progress, Back/Next, appropriate resume/skip, accessible localized workspace completion; and exact per-control icon/target binding, 44-unit targets, focus return, optional contextual panels, worked examples, isolated playgrounds, privacy, independent omission regressions and actual interaction/capture demands. These are bounded planning requirements, not a completed audit of all linked canonical sections.

Actual existing onboarding consumers include src/renderer/main.ts (setup progress and navigation), src/main/workspace-service.cjs (onboarding mutations) and src/main/security/workspace-contract.cjs (validated persisted onboarding shape). Existing tests include tests/workspace-service.test.cjs and tests/renderer/renderer-workspace.spec.mjs. These existing paths identify material for implementation review; their presence does not prove practical project setup completion or per-control info-button coverage. Current workspace-service source bindings remain separate in the phase architecture registry. No consumer path, runtime receipt, capture or completion evidence was invented for the new feature rows. Their proof arrays remain empty and hashes null.

Validation performed: node scripts/evidence/validate-ledger.cjs passed with 107 identities and 428 surface records. node --test tests/evidence-ledger.test.cjs passed 18 tests, including an independent negative check that removing the per-control guidance identity fails admission and exact checks of the new surface boundaries. No native Windows execution or complete feature acceptance was performed.

Remaining work: complete full canonical-section reconciliation and independent review for all 107 identities; admit the actual per-surface action/control inventory, concrete implementation consumers, localized articles/copy and persistence; exercise real setup effects and every capable control's actual rendered guidance; and collect source-bound built runtime/capture/native evidence. All full acceptance claims remain unverified.
