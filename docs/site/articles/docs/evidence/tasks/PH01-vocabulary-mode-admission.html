PH01 personal vocabulary and shared mode admission

This is a bounded implementation admission plan for the existing personal-vocabulary and school-mode identities. It preserves the 107-identity, 428-surface, 398-requirement inventory and all existing work IDs. Neither feature is accepted. The reusable core is undergoing corrections; the security article and active source must be reviewed again after that checkpoint. No private dictionary, payload, source metadata or user cache was opened or copied for this review.

Actual reusable consumers and limits

src/shared/personal-vocabulary.mjs provides the bounded parser, opaque selection and serialized controller, including explicit owned-copy/accessible-name formatting and a caller-supplied mode predicate. It contains no dictionary and performs no I/O. src/main/privacy/personal-vocabulary-cache.mjs is the private desktop cache candidate. src/shared/personal-vocabulary-indexeddb.mjs is the independent per-origin browser cache candidate. Their declarations expose portable consumer APIs. docs/security/personal-vocabulary.md describes the intended boundary and current integration gaps; its ongoing corrections are not treated as reviewed final behavior.

The predicate suppresses formatting and generic status when the mode is active; it is not a shared mode service, live watcher, rename implementation or credential verifier. The parser/controller alone does not provide a visible upload control, localized presentation boundary, settings search, palette route or export exclusion in another service. Separate controllers and browser tabs do not acquire a common mutation queue merely by importing the module.

Independent surface admission

Surface Eligible consumers Missing implementation boundary
A: installed application Shared controller and a dedicated IndexedDB database in the application's private Electron profile, owned by its single window/controller, are the selected consumer route. A host file-cache adapter is also available but is not automatically connected. Renderer-owned localization and accessible-name helpers are eligible presentation consumers. Semantic local JSON picker; visible no-file/load/invalid/replace/clear/corrupt controls; isolated cache ownership; payload-free typed status; all eligible copy/name consumers; shared mode integration; own settings/palette/regex routes. These remain desktop integration work.
D: public visitor website Shared browser-compatible controller and IndexedDB adapter on the visitor's own origin/profile, independent of the installed application. Website-owned visible settings control and text/name boundary, local cache ownership, own search/palette/regex routes and mode/capability handling. A download link or desktop redirect cannot satisfy D.
C: authenticated browser companion Shared browser-compatible controller and a private cache local to that client/profile, with its own presentation consumers. Companion-owned controls and formatting; authenticated bounded mode-state integration where required; payload must not travel to the broker, host or another device. Pairing grants no permission to share the visitor's dictionary. D behavior does not establish C acceptance.
R: repository/build/release process Generic schema documentation, payload-free tests, code/privacy review and leak-exclusion checks. R is outside the catalogue's user-facing feature surface for these two identities, not a fourth shipped vocabulary UI. R checks support A/D/C but cannot replace their delivery or admit private files into source, test artifacts, captures or publication.

A browser origin's local cache is not the universal shared mode record. A disconnected browser must state the actual unavailable shared-state capability; it must not silently invent an independent off state or claim cross-application propagation. Transport design must preserve explicit pairing, authentication and scoped authority without transmitting dictionary bytes.

Controlled presentation and isolated state

Use explicit localization helpers for shipped UI-copy segments and separate helpers for accessible names. Invoke formatOwnedText only after establishing that a segment is application-owned and eligible. Preserve commands, code, identifiers, URLs, paths, source records, model/provider text and factual external content as immutable separate segments. Never feed a mixed string containing those fragments into a generic whole-label rewrite. Render replacements as text, never HTML. A DOM crawler or an all-text global replacement is not an eligible consumer.

All three language modes need real copy/name consumers, including dynamic controls and dialogs. Shipped wording stays unchanged before valid import. Invalid replacement preserves the last valid cache; explicit clear removes it. Reload revalidates bytes and corruption returns to shipped wording. Serialize import/load/replace/clear at the actual cache ownership boundary; independent tabs or processes need their own explicit coordination. Document storage failures truthfully and preserve the previous usable selection.

Keep validated bytes only in the isolated private file cache or per-client IndexedDB store. Do not add cache, formatted private output, file names, paths, hashes, counts or other identifying metadata to ordinary settings, workspace snapshots, undo/history, sync, exports, notifications, logs, telemetry, diagnostics, prompts or captures. A generic export disclosure is required but does not itself filter data: review the actual export/history inventories and their consumers. Never route the dictionary through a normal project import/export operation or an authenticated companion message.

The always-visible semantic JSON upload control must exist even in the no-file state, with localized status and replace/clear actions, keyboard access and appropriate targets. Its own settings search and command palette must index/focus those controls. Plain text remains the search default; each applicable search/list/picker owns its adjacent anchored full regex builder. Browser-native picker restrictions require an honest documented alternative; they do not authorize an absent settings route.

Universal shared mode dependencies

  1. Provide one shared local application-data record with versioned state, chosen display name and shared credential reference. Metadata is separate from dictionaries and ordinary per-application settings. Credential material must not enter exports, source, logs, screenshots, telemetry or history.
  2. Watch the record and apply mode, rename and credential changes live in every running application. Unreadable or unwatched state must be visible on the control rather than assumed off. Browser integration needs an explicit authenticated design for the supported local/LAN relationship; per-origin storage alone cannot deliver universal synchronization.
  3. Keep the control discoverable in each surface's own settings and palette. After rename, use only the exact chosen name in labels, descriptions, results, notifications and accessible names; do not reveal the shipped mode name through a fallback route.
  4. Entering the mode forces English and omits Cantonese/bilingual, humor levels, personal-vocabulary and all themed surprise/photo/code-name controls, routes, search/palette results, previews, notifications and references. Disabled or visually hidden controls that remain discoverable are insufficient. Preserve prior preferences/cache without applying them; restore them only after successful exit.
  5. Leaving the mode requires the one shared locally verified PIN/password or passkey choice. Do not substitute per-element experience-lock credentials, a renderer Boolean or a shared static token. Provide the documented reset route and disclose that this is an experience lock, not a security boundary. Cancellation, unavailable verification and failed persistence remain incomplete.

Focused continuation and evidence

PH04 owns core/cache corrections and the shared-mode backend. Desktop integration follows in A; visitor integration follows independently in D after its current delivery; C retains an independent consumer and authentication boundary. The selected desktop vocabulary route keeps the file input, validated bytes and dedicated cache entirely inside the admitted renderer's private profile; it does not transfer the dictionary through ordinary IPC. Shared mode uses a separate host service and typed IPC. These are source plans, not runtime receipts. Priority order is: finish/review the reusable core corrections; implement isolated desktop cache ownership and controlled copy/name boundaries; implement visible settings/search/palette integration; provide real shared-mode storage/watch/rename/credential behavior; then admit independent D/C consumers and full suppression/restoration across their actual inventories.

Existing focused core/cache tests can establish only their exercised module behavior. Integration still needs no-file and all schema/error states, no partial apply, replace/clear/reload/corruption, concurrent ownership, actual export/history exclusions, no-network fallback, all three languages, suppression/restoration, renamed-mode discovery, live propagation, credentials/reset, keyboard/screen-reader operation, phone/high-scale layouts and genuine source/build-bound captures per surface. Windows/native and account-dependent proof remain deferred or unverified. No new test run, runtime receipt, capture or completion claim is made by this admission note; full roadmap and canonical-detail coverage remain open.
