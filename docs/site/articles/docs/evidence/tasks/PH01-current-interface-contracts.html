Existing implementation candidates

  • website/app.js contains a source-to-image task walkthrough, selectable steps, per-browser completion and reset, generated example previews, troubleshooting questions and saved references. This is an interactive documentation candidate rather than only a Markdown directory. Built/deployed interaction, persistence, accessibility and complete task/article coverage require separate verification.
  • The icon update at source 0885109 adds src/renderer/material-icons.ts and bundled SVG assets with provenance.json and license metadata. Shell and diagram controls consume the shared icon helper. The diagram workbench now uses 48 by 48 button bounds; its former text-glyph and 32-pixel implementation is superseded. Complete rendered conformance and native interaction remain unverified.
  • scripts/documentation/bundle.mjs and src/main/documentation/service.cjs now implement bounded offline article/asset bundling and validated article list/read/internal-link consumers. vite.config.mjs invokes bundling, src/main/index.cjs supplies the packaged documentation directory, and typed documentation operations reach the service. This supersedes the earlier finding that the offline documentation backend and bundle were absent.
  • src/renderer/documentation-panel.ts and documentation-search-worker.ts are active reader candidates with article navigation, formatted host-admitted HTML, headings, literal/regex search and unavailable-resource explanations. Reader integration is still settling; file presence is not proof of a complete bundled article inventory, accessible interaction or native offline behavior. tests/documentation-service.test.cjs and tests/renderer/renderer-documentation.spec.mjs are focused verification candidates, not claimed passing results in this update.
  • src/renderer/diagram-workbench.ts implements node selection, pointer dragging, snapping, keyboard layout movement, pan/zoom, fit, undo/redo, structured node selection and explicit layout persistence. Layout and semantic apply are distinguished.
  • src/renderer/package-panel.ts routes dependency selection/removal into its actual package model and uses reviewed file previews and hash/revision-bound apply. src/main/configuration/package-authoring.cjs and package-model.cjs are concrete host-side consumers. The canvas is not merely a decorative dependency image; full recipe coverage and actual Buildroot acceptance remain separate obligations.
  • src/renderer/guest-topology.ts routes network/storage/hardware inspectors through managed guest preview/edit requests and consent. Native hypervisor readback and real guest acceptance remain separate obligations.
  • tests/renderer/renderer-canvas.spec.mjs contains synthetic service-fixture interactions for dependency removal, package preview invalidation, layout history/persistence conflict and revision-bound guest topology edits. These tests describe focused interface behavior; they do not prove native guest or Buildroot execution.
