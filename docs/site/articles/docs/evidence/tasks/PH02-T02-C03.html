Confirmed preference and local draft reset

Current renderer SHA-256: 122575c891c1c9c4e2a9d4a852d6b61a196b459faf598197ff52be0361623114. Current browser specification SHA-256: 1f025eafa99197cb51d21d42efd61b3d66273fd575d15b0fd0c2b1ada0fe5b1f.

The language panel now shows its last confirmed value and actual origin, distinguishing an application default from a saved preference. The pending selection remains separate. Discard choice restores only that pending selection to the confirmed value, issues no host call, and returns keyboard focus to the language select. The action is disabled when unchanged, saving, unavailable, or awaiting restart after an unknown outcome or failed refresh. The handler applies the same admission check. The wording deliberately says last confirmed, because a lost response cannot establish the current saved value.

Strict TypeScript checking and all 29 source-preview browser cases passed. The four additional cases verify default/saved bilingual provenance, keyboard draft reset with zero host calls, and reset to a refreshed conflict value. Existing cases additionally check that unknown/failed-refresh outcomes disable reset, unavailable storage shows no confirmed provenance, and successful saves update the confirmed origin. The twelve language/theme/viewport tuples continue to pass, including the two-action layout. This newer renderer has not inherited the earlier release's packaged or native verification below.

Reproduction

Install the locked dependencies and a supported Playwright Chromium browser, then run:

npm run test:renderer

For a preinstalled Chromium executable, set PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH to its absolute path. The test server binds only loopback, refuses an occupied port and is owned and closed by Playwright. Outputs stay in ignored .cache/renderer-test-results/. The source-preview document shows fixture provenance intentionally.

Limits and next acceptance

Early screenshots sometimes captured a selected-language field before its text became visible. Material Web sets displayText before a nested field completes its 67 ms delay and 83 ms opacity transition, so property readiness alone was insufficient. The capture matrix now checks the exact selected label in both the component property and rendered text, waits for nested content opacity to reach 1, and waits for font readiness. All 12 presentation cases passed with these conditions against unchanged renderer bytes. Independent inspection of all 12 refreshed PNGs confirmed correct visible language text, clear selected navigation and no visible horizontal clipping. These captures show the top of the scroll area; narrow captures do not show the Appearance section. No fixture screenshot was promoted to current native product evidence.

Run the exact root Windows entrypoint from the published source and verify the resulting installed renderer, native window actions, keyboard/recovery paths and source-bound captures. Browser fixtures do not prove native input, IPC, persistence across process restart, operating-system DPI, installer/update behavior or full feature acceptance. Existing historical native receipts retain their original revisions. The owner authorized resumption after the preservation checkpoint; continue publishing verified work directly on main.
