Durable jobs and local safety services

香港粵語

The host-only src/main/jobs/manager.cjs accepts an explicit registry of adapter functions. A renderer cannot supply an executable, command, PID, or adapter implementation. The host must validate each adapter payload against its operation schema before enqueueing it. The manager itself accepts bounded JSON payloads; this is not a substitute for adapter admission or file capabilities.

createJobManager({ directory, adapters }) returns enqueue, get, list, run, cancel, retry, and page. The host retains exactly one manager per owned directory. Enqueue requires kind, payload, and ownerId; an optional operationId makes identical requests idempotent and conflicting reuse fails. run(id, ownerId, expectedSequence), cancel, and retry enforce exact ownership and observed sequence. Retry creates a new job linked by retryOf, preserving the original record and partial outcomes.

Adapters receive (payload, { signal, jobId, log, item, checkpoint }). Await adapter completion before reporting final cancellation: an abort request changes running to cancelling, and final settlement changes it to cancelled. Adapters must observe the signal and terminate only resources they own. A disconnected observer is not evidence of cancellation. Queued jobs cancel without running. Exceptions produce a generic failure without persisting raw exception secrets. Results, checkpoints, logs, and item outcomes must be sanitized by their admitted adapter before persistence; never include credentials or raw authenticator material.

Job metadata uses same-directory exclusive temporary files, file flush, and atomic rename. Every log or item record occupies a separate durable JSON file; page(id, 'item' | 'log', { after, limit }) reads at most 100 records, with monotonically numbered cursors and no automatic pruning. There is no fixed total queue limit. The metadata catalogue is currently loaded in memory; full unlimited catalogue paging remains future work. Item records should name succeeded, failed, skipped, or uncertain outcomes, destination identity, verified output hash, and safe next action as appropriate to the adapter. The manager preserves these typed JSON values without claiming output verification itself.

Reopening storage preserves queued/final jobs and converts running/cancelling jobs to interrupted with a new sequence. It does not resume external work or claim rollback. The host must inspect actual owned runtime state and recoverable output before offering safe retry. Directory flushing on every supported filesystem, independent-process locking, orphan-file reconciliation after a power-loss window, and large catalogue scaling are not implemented acceptance claims. Do not open the same directory from multiple processes. No native Windows crash/power-loss test was run.

createConfirmationService issues short-lived exact operation/destination challenges with two separately generated keys. Confirmation requires both exact keys and slider value 1. The returned random token is consumed once, including on a failed binding attempt. Changing the operation or destination, expiration, cancellation, replay, or an incomplete slider rejects authority. The host must derive the exact canonical destination from a validated device/file capability, consume immediately before the destructive operation, and revalidate that capability again. These in-memory tokens vanish on restart. UI independent-key entry, focus restoration, clean-rebuild explanation, and physical-device identity revalidation are separate integration requirements; no destructive device test was run.

totp and verifyTotp implement RFC 6238 with SHA-1, SHA-256, and SHA-512. The focused suite checks all eighteen Appendix B vectors. createAuthenticator requires host-provided protected-vault read/write functions. Enrollment returns only an ID and protected reference; the renderer must never receive the stored secret through this service. Manual/QR provisioning, protected enrollment UI, OS-vault wiring, replay counters, rate limiting, and authenticated companion pairing remain pending. A TOTP match is not itself a broker capability grant, and experience policies must never become broker authentication.

Validation: node --test tests/jobs.test.cjs tests/confirmation.test.cjs tests/authenticator.test.cjs tests/experience-policy.test.cjs tests/notifications.test.cjs passed sixteen tests on Linux on 2026-10-15. This proves the bounded service behavior exercised by those tests, including durable page reads after reopen, ownership/stale-sequence rejection, cancellation settlement, retry lineage, restart interruption, confirmation expiry/destination rejection, and RFC vectors. It does not complete PH04 or application/browser/native acceptance.

Experience policies, local tickets, and waiting recovery

src/main/security/experience-policy.cjs exports createExperiencePolicyService({ directory, vault, now, openFolder, attempts, waitMs }). The directory must be the actual app-data recovery destination; the host supplies its trusted file-manager callback and vault. All six policies are enumerated by policies: pin, password, pin+password, password+totp, pin+totp, and password+pin+totp.

enroll({ targetId, policy, credentials, confirmation, duration, disclosureAccepted }) creates independent vault material per target and requires repeated factor values plus a valid current TOTP for OTP enrollment. PINs and passwords are salted scrypt hashes in the vault, never persisted plaintext. Duration is { mode: 'surface' | 'minutes' | 'session', minutes }. list, get, isLocked, requireUnlocked, unlock, relock, leaveSurface, and remove operate on exact target identities. All policies start locked after process restart. Unlock sessions live only in memory. Vault unavailability does not consume an attempt or downgrade the required factors. Concurrent verification of one target is refused. The UI must enforce requireUnlocked at every protected action route and supply anchored ordered factor/keypad UI; service methods alone do not intercept DOM events.

Wrong answers decrement the shared per-target attempt allowance. Exhaustion produces exponentially escalating waits capped at one hour. challenge(target, { schoolMode }), hit(nonce, cell), and answer(nonce, value) implement the recovery ladder: five wrong four-choice dish answers lead to ten sums, a wrong sum leads to a timed mole round, a failed round leads to the original clock. School mode starts directly at sums. All grading uses in-memory host challenges and single-use nonces. Mole hits use host receipt times and count each visible mole once; submissions before round completion are rejected. Clearing a challenge ends only the wait, returns the same attempt count as serving the clock, preserves escalation, and never unlocks the element or grants broker authority. Skip timestamps persist and allow at most three skips per rolling hour across all elements. Backward clock movement cannot shorten a wait or replenish the skip budget within a running service; the persisted last mutation time bounds restart clock handling. Challenges vanish on restart. Browser-native policy storage and integration are separate consumers.

createTicket, tickets, and advanceTicket retain local fictional support records. recovery returns the exact configured folder plus the invariant local-only disclosure. openRecoveryFolder invokes only the host-supplied file-manager callback and propagates unavailable/failure outcomes. This service contains no recursive deletion or network request. Tickets, policies, and skip accounting are persisted atomically. UI localization, search/bulk affordances, accessibility, and every-element action interception still require integration evidence.

Notification and changelog records

src/main/jobs/notifications.cjs exports createNotificationStore({ directory, now }) with notify({title, message, severity, context}), review({notificationId, status}), changelog({version, date, sourceUrl, changes}), and page({after, limit}). Notifications, read/dismiss/resolve events, and factual changelog entries are immutable numbered files; review never removes the original event. Pagination loads no more than 100 event files per call. No automatic retention pruning occurs. Changelog URLs must be HTTPS without embedded credentials. All message/change strings are data: render them as text, never HTML. The host must sanitize operation context before recording it. Rich upstream markup sanitization and bundled offline article content are separate UI/content integration work.

Storage admission

Shared storage checks every existing path component and rejects symbolic links before reads/writes, uses no-follow file descriptors where supported, validates job UUID identities and counters before deriving filenames, and validates paged record sequences. Failed metadata writes leave the prior committed metadata and in-memory job unchanged; temporary write files are cleaned. This is not an OS-wide locking or hostile concurrent-filesystem-race guarantee. Run a single trusted host manager per directory. Optional owner filtering is available on get(id, ownerId), list(ownerId), and page(id, channel, pagination, ownerId); IPC wrappers must always supply the authenticated host-owned identity.
