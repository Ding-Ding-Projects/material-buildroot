ISO 執行環境與資源

English · 欄位目錄

用途與建議預設

Buildroot 需要 Linux 執行環境。Easy 模式會透過主機查詢項目已儲存嘅環境，顯示實際 WSL 發行版或已認可嘅 Docker 映像，唔會推薦未驗證嘅映像名稱。開始前，先喺 Runtime 工作區選擇並授權該環境。

例子與限制

例如，可以使用本機偵測到嘅 WSL 發行版，透過既有控制項選取。Docker 則需要已認可嘅 Linux 建置映像，並以非 root 身分執行，冇一個可以套用到所有項目嘅通用映像名稱。

引導建置會使用兩個並行工作同既有排程器預設。並行工作好似同時開幾張工作枱：數量多咗會佔用更多 RAM 同儲存空間，資源有限嘅主機反而可能變慢。先用引導預設，再按實際觀察調整，唔好單憑數字大就當一定快。

復原與進階控制

欠缺執行環境、架構唔支援、資源不足或權限失敗，都會保持未完成。請透過執行環境設定處理顯示嘅原因，再重新整理 ISO 計劃。原有 Build 控制項仍可手動設定並行數量同資源預留。引導 ISO 按鈕刻意唔接受原始 shell 指令或任意執行環境字串。

已儲存執行環境控制項嘅選用說明

「已儲存執行環境」正上方嘅 44 像素資訊按鈕，只會說明專案已回傳嘅 WSL 發行版或 Docker 映像參照；資料欠缺就明確顯示身分未明。已儲存值唔代表目前有存取權、已授權或已就緒。環境欠缺或無法存取時，請返回「專案同執行環境」核對環境同權限，再重新檢查 ISO 所需設定。

說明保留既有兩個並行工作要求。「試行兩工作例子」用四項模擬工作共用兩個位置，顯示兩項執行、兩項等候，唔會開始真實工作、呼叫主機或寫入儲存。「重設執行環境例子」、關閉、移除元件或切換專案都會清除例子，重開時由空白開始。例子唔會選取其他執行環境或資源設定。

已註冊 Material 資訊按鈕有本地化名稱、提示、展開狀態、Enter/Space 操作同 Escape/關閉後焦點返回。真正原生按鈕透過組合說明共用嘅 @material/web 2.5.0 適配器，以元素參照連到本實例嘅說明同提示。各實例唔會共用關聯或例子。舊引擎欠缺相關 API 時，鍵盤操作仍然可用，但關聯未能提供。來源瀏覽器檢查唔等於原生驗收，後者仍然待完成。
