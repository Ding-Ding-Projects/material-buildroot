建立及開啟專案

English · 專案索引

「專案及執行環境」提供開啟、建立、接入、匯入描述檔、匯入已解壓來源及複製操作。建立使用官方 Buildroot HTTPS 來源及附有查核日期嘅長期支援版本建議。複製接受另一個經驗證嘅 HTTPS 來源同分支或標籤。兩者沿用主機來源服務，由原生資料夾選擇器選擇父目錄，明確信任來源，再提供未使用嘅子目錄名稱。現有目的地唔會被取代。輸出目錄會喺來源旁邊獨立建立；登記失敗可能留下已複製來源，之後可以接入，唔會為咗報成功而刪除。

接入操作透過原生選擇器分別選擇現有工作區、Buildroot 來源及獨立輸出目錄。「匯入已解壓來源」使用同一個非破壞登記流程，唔會解壓壓縮檔或者複製來源，現有設定同輸出內容會保留。

開啟會列出保留嘅描述記錄，並分清本次工作階段已授權專案同需要重新選擇資料夾嘅記錄。儲存路徑唔代表檔案存取權。直接開啟需要現有專案授權及最新身份檢查；重新啟動後要再次選擇資料夾並明確信任來源，主機唔接受由顯示層交來嘅檔案系統路徑。

可攜專案描述檔

匯出使用 material-buildroot-project JSON 第 1 版，包含名稱、執行環境、依序排列嘅外部樹資料，以及來源快照：解析後修訂、分支、修改狀態、觀察時間及可用性。描述檔唔包含憑證、來源或輸出內容、主要資料夾路徑或者執行能力。外部樹路徑會作為資料保留；路徑敏感時，請保護匯出檔案。

匯入使用原生 JSON 選擇器及有界解析器，重複鍵、未知版本、額外欄位、無效選項或者來源資料會喺登記前被拒絕。檢視後嘅匯入只可使用一次，十五分鐘後失效。原生專案需要重新選擇工作區、來源及輸出並信任來源；WSL 描述檔則喺記錄中指定嘅發行版開啟專用選擇器，取得新主機收據。位置不可已登記，成功後產生新本機 UUID，唔取代現有專案或檔案。

匯入選項同原有來源快照會保留。再次匯出仍標示原始快照，唔會當成新觀察；獨立嘅來源更新先會查詢現況。外部樹需要自己嘅授權，路徑唔會恢復存取。匯入唔會切換至記錄中嘅修訂，亦唔證明本機內容相同。部分資料寫入失敗會撤銷本次專案授權，可能保留可復原嘅目錄記錄，但唔會刪除來源或輸出或者宣稱成功。

原生同 WSL 接入使用可取消嘅保留工作區流程。新身份開啟獨立面板，已有身份則聚焦原面板。執行環境控制讀取該面板實際主機選項；身份改變後，過期回覆會被忽略。

來源及執行環境資料

更新專案來源資料會顯示實際來源及輸出路徑、解析後修訂、目前分支或分離狀態，以及本機修改。要求嘅標籤唔等於已切換修訂，無法取得狀態會明確標示未核實，包括冇普通 Git 歷史嘅來源樹。

現有建議為 Buildroot 2025.02.18，源文章記錄於 2026-10-16 查核官方下載頁，當時 2025.02.x 長期支援至 2028 年 3 月。呢個係有日期嘅指引，唔係自動更新嘅最新版聲明。信任及複製前可以選擇其他明確分支或標籤。

WSL 或以摘要鎖定嘅 Docker 選擇按專案保留。重新開啟已授權專案會載入其選項。接入同複製唔會開始建置或執行來源程式。WSL 原生資料夾權限由發行版綁定流程提供，普通選擇器唔會取得任意 UNC 權限。

驗收界線

此內容描述建置交付模式下嘅來源實作，未完成執行、操作、無障礙、持續儲存及畫面驗收。壓縮檔解壓、即時版本探索同來源升級屬獨立工作，唔能夠由建立專案推斷已完成。
