取得來源及管理修訂

English · 功能索引

來源工作區透過 HTTPS Git 取得 Buildroot，檢視目前修訂及本機修改，並將取得更新、預覽同套用分開。官方取得操作固定使用 https://gitlab.com/buildroot.org/buildroot.git；自訂 HTTPS 來源有獨立明確信任確認。兩者都唔會取代已經有內容嘅目的地。

保留及套用修訂

  1. 接入可信來源專案，再更新狀態。
  2. 如需保留目前已提交修訂，建立快照。有本機修改時不能建立快照。
  3. 取得分支或標籤，呢一步唔會切換來源內容。
  4. 檢視不可變目標修訂、修改檔案摘要及完整有界文字差異。
  5. 閱讀相容性提示，明確接受已檢視修訂。
  6. 套用會再次核對原修訂同本機修改狀態，通過先切換至分離修訂。

每次套用前，refs/material-buildroot/snapshots/ 下嘅獨立參照保留上一個提交，建立時要求參照原本不存在。重新啟動唔會刪除呢啲參照。更新列出最新 100 個快照，較舊參照仍保留。揀選舊快照會建立新回復預覽，仍需再次確認套用，唔改寫使用者分支。

快照只保留已提交來源，唔備份未提交檔案、被忽略檔案、未儲存設定草稿、外部樹或者建置輸出。之後切換失敗仍保留快照，先更新狀態再決定復原。切換拒絕覆寫被忽略檔案，唔使用重設、強制切換、自動暫存或者來源刪除。

預覽及相容性

預覽十分鐘後失效。每個子程序最多輸出 4 MiB，過大差異會停止建立預覽，唔容許以不完整內容套用。二進位內容唔會當文字顯示。工具鏈、架構、設定、套件、核心、啟動同建置基礎設施變更分類只係提示。

輸出檔案會保留，但同新來源嘅相容性仍未知。切換來源唔會自動遷移設定、失效建置戳記或者重新建置輸出。下一次建置前請重新檢視設定。來源變更取得既有來源租約；WSL 專用流程喺操作期間持有來源及輸出租約。

WSL 權限

WSL 操作使用主機專用流程，唔借用普通 Windows 路徑權限。程序內有效收據綁定發行版、啟動 ID、機器 ID、非 root uid，以及根目錄、來源及輸出嘅裝置與 inode。每次 Git 呼叫都喺執行 Git 嘅同一程序重新核對身份，改變或者無法查核就停止。參照係傳給固定主機程式嘅已驗證資料，顯示層唔可以提交 shell 腳本或者檔案路徑。

WSL 取得來源沿用固定官方來源流程。修訂管理要求已接入普通 Git 來源樹同當前收據；重新啟動後，持續儲存嘅專案資料唔會恢復權限，要重新原生接入。原有簡單 ASCII Linux 路徑限制繼續適用。

發行壓縮檔限制

官方下載頁提供發行壓縮檔及分離 PGP 簽署，但本流程未實作取得及解壓。程式冇已授權嘅 Buildroot 壓縮檔簽署查核，亦冇來源專用保留連結解壓器。通用解壓器拒絕連結，唔可以為此放寬。下載後自己計算摘要唔係獨立上游認證。

請用支援嘅官方 HTTPS Git 取得流程。HTTPS 認證傳輸端點，唔證明提交或者標籤簽署，此流程唔宣稱已驗證簽署。

驗收狀態

來源實作及正式建置結果同執行驗收分開。本輪延後測試、靜態分析、審查、實際來源切換、WSL 執行及畫面擷取。保留、重新啟動探索、外部並行寫入、Git/WSL 失敗復原及完整本地化操作仍待驗收。
