# API collections

- [Pair, inspect, act and disconnect safely](api-workflow.md) · [香港粵語](api-workflow.zh-HK.md)

The [master Postman collection](material-buildroot.postman_collection.json) and its category file are a snapshot of the original four HTTPS companion routes and six baseline actions. New host-admitted `actionContracts`, pairing fields and client-binding headers require regeneration from the exact integrated contract before current completeness can be claimed. The opt-in HTTPS companion is the product HTTP surface; its category collection and original usage are documented in [the companion article](../security/companion.md#postman-collections).

Desktop IPC boundaries are not HTTP and have no collection. They are listed in the [security index](../security/README.md).

Both files are generated by `node scripts/api/generate-postman.cjs` and checked by `tests/postman-collections.test.cjs`.

The generator detects the integrated host `src/main/security/companion-consumers.cjs` module. When present, it enumerates that module's actual action contracts and scopes, uses authored argument templates, adds the reviewed browser pairing field and session client-binding header, and refuses generation for an action without an authored example. When absent, it generates the explicitly labelled six-action baseline snapshot. Regenerate after consumer integration; source support for expansion alone does not update the JSON files. Examples are not session grants. Native-confirmation-required operations still require desktop approval, and all actual API execution remains unverified in this delivery mode.
