# Material Buildroot screenshot gallery

This is a bilingual, provenance-bound screenshot gallery prepared for the Material Buildroot Pages site. After the parent repository publishes this change, the nested site will be available at `https://ding-ding-projects.github.io/material-buildroot/gallery/`. This is a nested site in the main repository; a separate gallery repository was not created.

The gallery contains 67 reviewed original PNGs across 13 collections. All 51 earlier records and files remain unchanged; 16 additional source-bound captures are listed below.

- 24 retained workspace renderer captures from source revision `e8f9bebf2b96397b00000be485870a61c16cb3e2`, plus 9 historical workspace captures from `7c14df34ffe785e2a7e108b17f839e15668d1183`.
- 2 historical desktop-shell captures from `3f5d2cd5bbdafbeda324514c3db0da9f0328bcfd`, 1 native dialog capture from `e722cf1b91ccc46465eb449df4abd84d9d6df2a1`, and 1 installed startup capture from release `v0.1.1-build.232.1` and source `00bca0993c22a30c6c5071458489c01331c67d2e`.
- 6 earlier documentation-site captures and 6 newer source-preview article captures from `8db4e8519a27e1a3878d96714717f68432af7ed1`. The latter source run remains `FAILED` on status-navigation focus and does not establish deployed delivery.
- 2 bilingual runtime-guidance source fixtures from `599d68a494cc9a177122f3f4ead4fbbae8b10da7` and `d6f098d10f1b503f94a0a7b2b798f66118ecf2e7`; neither records an individual capture clock.
- 4 successful guest-console captures and 2 failed alternate-profile captures from product source `5431a6275d875428ae50335905107d5951cc6150`, all bound to ISO SHA-256 `1d75d40b94e3c441aaaead9109f8074f62334931e1d84a576f3d7a36ec566dba`.

The 24 renderer captures remain bound to `e8f9beb` and do not show every later screen. The installed-workspace image records one startup state and return route; the native dialog image records one stable dialog. The six documentation source-preview captures from `8db4e85` are not deployed-site proof, and their overall browser receipt remains failed. The two runtime-guidance images are source-test fixtures with unavailable capture times. The ISO images are limited to the exact artifact hash and QEMU profiles stated on their cards; they do not establish physical hardware, UEFI, persistence, Internet connectivity, or general compatibility.

Each image is byte-for-byte identical to its reviewed source. `captures.json` records its SHA-256, image pixel dimensions, recorded viewport (when known), capture time when the source recorded one, source provenance, and evidence boundary. Website preview receipt-check timestamps are kept separate from capture time. Where the source did not record an individual capture clock, capture time is explicitly unavailable; it is never inferred from a filename or filesystem timestamp. The current interactive-site preview was built from a source snapshot whose inputs differed from base commit `c527753`; the separately recorded delivered source commit is `3de9822`. The historical landing refresh likewise records its build base and delivered commit independently.

The browser interface uses locally bundled `@material/web` 2.4.1 controls. Search, collection chips, language choice, light/dark theme, and provenance disclosure act only on this gallery in the browser. Language and theme preferences are stored locally in the browser. The layout supports 320 CSS-pixel screens, keyboard interaction, and reduced-motion preferences.

To rebuild the local Material bundle from this repository root with the already installed website toolchain, run `./website/node_modules/.bin/esbuild gallery/components.js --bundle --format=esm --target=es2022 --minify --alias:@material/web=./website/node_modules/@material/web --outfile=gallery/assets/material-components.js`, then copy that file to `docs/gallery/assets/material-components.js`. The alias pins package resolution to the admitted `website/node_modules/@material/web` 2.4.1 instead of a different root-level package. Keep `gallery/THIRD_PARTY_NOTICES.txt` beside the source and copy it to `gallery/assets/THIRD_PARTY_NOTICES.txt` and `docs/gallery/assets/THIRD_PARTY_NOTICES.txt`; no new package is required. The bundle metafile check confirmed all 83 Material inputs came from that pinned directory.

## Source inventory and exclusions

The review examined 112 tracked image paths under `docs/evidence`, `docs/gallery`, and `website`: 102 match the earlier 51 gallery image hashes, one is a byte-identical duplicate of the new native dialog capture, eight distinct receipt-bound tracked captures are added, and one tracked file is excluded. `docs/evidence/iso-boot/grub-menu.png` (SHA-256 `4ccc4220e6c26db9b5089213aa2cd69c427b96792c55a9595623925d76853303`) is absent from `docs/evidence/iso-boot/acceptance.json` and has no validated capture record.

Eight ignored source-preview images were inspected and published from exact image hashes and source receipts. Two other ignored profile-guidance images, SHA-256 `2a4f8cd249e230176a7d60552017920ce0ec5f33e65e9b68a4ee37d2cfb04898` and `8d8672d819ea4c5a462cbbc9292b7ba09be9d99b221e79c2dada6085d823e857`, remain withheld because their image-to-source provenance is not established. Other private cache material was not part of the bounded review and was not considered for publication. This includes native-crash investigation material, which remains unreviewed for gallery use. A user-provided installer dialog image was withheld because it contains machine details and has no source-bound capture receipt. The six receipt-listed PPM originals remain unchanged beside the ISO acceptance evidence; the gallery copies only the matching PNG renditions. No local filesystem path or private source is published.
